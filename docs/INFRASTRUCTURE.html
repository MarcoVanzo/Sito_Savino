01 Panoramica Architettura

L'intera infrastruttura è ospitata su DigitalOcean nella region Frankfurt (fra/fra1), garantendo bassa latenza per gli utenti europei e comunicazione veloce tra i componenti.

DigitalOcean — Region Frankfurt (fra / fra1)
Colocalizzazione Tutti i servizi sono nella stessa region Frankfurt. La latenza app↔database è <2ms (rete privata). La latenza utente italiano→server è ~18ms.

03 Servizi DigitalOcean — Dettaglio

3.1 — App Web (sito + CMS)

È il container principale che serve tutte le pagine web. Quando un utente visita il sito o un admin accede al CMS, questa macchina elabora la richiesta PHP e restituisce la pagina HTML.

Slug apps-s-1vcpu-1gb-fixed CPU 1 shared vCPU RAM 1 GB Bandwidth 100 GB/mese Region fra (Frankfurt) Istanze 1 (fissa, no scaling) Web server heroku-php-apache2 Costo $10.00/mese

3.2 — Worker (code)

Processa i job in background. Resta in ascolto sulla tabella jobs nel database e quando trova un nuovo job, lo esegue senza bloccare il browser.

Slug apps-s-1vcpu-0.5gb RAM 512 MB Run command queue:work --sleep=3 --tries=3 --max-time=3600 Costo $5.00/mese
JobTriggerAzione
AnalyzeGalleryImageJobUpload foto nel CMSScarica immagine da S3, invia a CompreFace per riconoscimento facciale, salva risultati nel DB

3.3 — Database MySQL 8.4

Contiene tutti i dati strutturati dell'applicazione. Ogni pagina web legge da qui, ogni azione nel CMS scrive qui. È un database managed — DigitalOcean gestisce backup, aggiornamenti e monitoring.

Engine MySQL 8.4 LTS Size db-s-1vcpu-1gb (1 vCPU, 1 GB RAM) Nodi 1 (singolo, no replica) Connessione Rete privata (non esposta a internet) Backup Automatici giornalieri (inclusi) Costo $15.23/mese

3.4 — Spaces S3 + CDN

Storage dei file — un object storage compatibile con Amazon S3, con CDN incluso per servire le immagini dal nodo più vicino all'utente.

3.5 — Droplet CompreFace

Server dedicato che esegue CompreFace, un sistema open-source di riconoscimento facciale basato su deep learning. Analizza le foto della galleria per identificare automaticamente le giocatrici.

OS Ubuntu 24.04 LTS CPU 2 vCPU RAM 4 GB (Java + modello ML) Disco 80 GB SSD IP 157.230.98.6 Porta API 8000 Costo $24.00/mese

04 Flusso delle Richieste

Visita sito pubblico (es. /news)

UtenteRichiede GET /news via HTTPS
App WebControlla la cache (CachePublicResponse middleware)
App WebCache HIT → restituisce HTML in <5ms. Cache MISS → continua al passo 4
MySQLQuery per recuperare post, categorie, media
App WebRender SSR con Inertia/Vue.js, salva in cache per richieste future
CDN SpacesServe le immagini (hero, thumbnail) dal nodo più vicino all'utente

Upload foto galleria (CMS)

AdminCarica foto dalla sezione Galleria del CMS
App WebSalva l'immagine originale su Spaces S3
App WebINSERT in gallery_images + INSERT in jobs (accoda analisi)
App WebRisponde all'admin: "Foto caricata ✅"
WorkerPreleva il job dalla coda, scarica l'immagine da S3
CompreFaceAnalizza i volti e restituisce: coordinate, identità, % confidenza
WorkerUPDATE gallery_images con risultati, DELETE job completato

06 Build e Deploy

Pipeline

git push main → GitHub webhook → DO App Platform → Build → Deploy → ACTIVE

Build Web

composer install --optimize-autoloader --no-dev && npm install && npm run build
StepAzione
ComposerInstalla dipendenze PHP (autoloader ottimizzato, no dev-dependencies)
NPM installInstalla dipendenze frontend (Vue, Vite, Tailwind...)
NPM buildCompila assets + SSR bundle (bootstrap/ssr/ssr.mjs)

Build Worker

composer install --optimize-autoloader --no-dev

Solo dipendenze PHP (il worker non serve frontend).

Avvio Worker

php artisan queue:work --sleep=3 --tries=3 --max-time=3600

Polling ogni 3 secondi, max 3 tentativi per job, riavvio ogni ora.
